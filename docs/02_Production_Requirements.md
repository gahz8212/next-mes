# 02. 상용 MES 전환을 위한 핵심 요구사항 명세서
**작성일:** 2026-08-12
**목표:** 단순 프로토타입을 넘어 실제 제조 현장에 투입 가능한 생산 수준(Production-Ready)의 시스템 구축

---

## 1. 하드웨어 통합 및 사용자 경험 (Hardware & UX)
현장 작업자는 마우스나 키보드를 거의 사용하지 않으며, 오직 스캐너와 직관적인 피드백에 의존합니다.

* **[ ] 글로벌 바코드 스캐너 리스너 (HID/Serial 감지)**
  * **요구사항:** 웹 페이지의 특정 입력창(Input)에 포커스가 없어도, USB 바코드 스캐너의 입력을 백그라운드에서 가로채는 전역(Global) 이벤트 리스너 구현.
  * **기술요소:** `keydown` 이벤트 캐치, 입력 딜레이(Debounce) 계산, 스캐너의 종결 문자(`Enter` 또는 `CR/LF`)를 인식하여 API 페이로드로 자동 변환.
* **[ ] 직관적인 오디오/비주얼 피드백 (Audio & Visual Alerts)**
  * **요구사항:** 스캔 결과에 따라 작업자가 화면을 보지 않고도 인지할 수 있도록 즉각적인 반응 제공.
  * **기술요소:** 브라우저 Audio API를 활용한 정상(띠딕!), 불량/오류(삐빅- 엑스!) 사운드 재생 및 화면 전체의 색상 점멸(Red/Green 플래시 효과).

## 2. 공정 무결성 방어 로직 (Poka-yoke & Data Integrity)
휴먼 에러를 시스템이 강제로 막아내고(포카요케), 데이터가 꼬이는 것을 방지해야 합니다.

* **[ ] 공정 순서 검증 (Routing Validation)**
  * **요구사항:** 이전 필수 공정을 누락했거나, 이미 완료된 제품을 재스캔한 경우 시스템이 가동을 차단해야 함.
  * **기술요소:** API 단에서 `barcode_history`를 조회하여 "SMT 공정 완료 여부"를 체크한 뒤, 누락 시 `HTTP 409 Conflict` 반환.
* **[ ] 트랜잭션 및 동시성 제어 (Transaction & Concurrency)**
  * **요구사항:** 네트워크 지연으로 인한 더블 클릭/이중 스캔, 혹은 여러 라인에서 동시 스캔 시 데이터 중복 적재 방지.
  * **기술요소:** DB 레벨의 `UNIQUE KEY` 제약조건 설정 및 PHP PDO의 `beginTransaction()` / `commit()` / `rollBack()` 적용.

## 3. 실시간 동기화 (Real-time Synchronization)
개별 PC가 아닌, 공장 전체가 하나의 뷰를 공유해야 합니다.

* **[ ] 무새로고침 대시보드 동기화**
  * **요구사항:** 1번 라인에서 제품을 스캔하면, 새로고침 없이 2번 라인 PC와 사무실 모니터의 생산량 게이지가 즉시 올라가야 함.
  * **기술요소:** PHP 환경에서 가장 안정적인 **SSE (Server-Sent Events)** 방식 적용. 백엔드에서 변경 사항을 Push하고, 프론트엔드의 `EventSource` API가 이를 수신하여 DOM 업데이트.

## 4. 시스템 복원력 및 로깅 (Resilience & Auditing)
현장 네트워크는 언제든 끊길 수 있으며, 문제는 반드시 추적 가능해야 합니다.

* **[ ] 오프라인 대응 및 큐잉 (Offline Queue)**
  * **요구사항:** 공장 와이파이 단절 시 스캔한 데이터가 날아가지 않도록 보존.
  * **기술요소:** 네트워크 오류 시 프론트엔드 `localStorage`에 데이터를 임시 큐(Queue)로 적재하고, 통신 복구 시 일괄 동기화(Sync)하는 로직.
* **[ ] 백엔드 데일리 파일 로깅 (Daily File Logs)**
  * **요구사항:** DB가 뻗었을 때 에러의 원인이나 누락된 데이터를 추적할 수 있는 텍스트 형태의 2차 백업.
  * **기술요소:** PHP `error_log` 및 Monolog 패키지를 활용해 `logs/mes_YYYYMMDD.log` 형태로 상세 스캔 이력과 시스템 에러 기록.
